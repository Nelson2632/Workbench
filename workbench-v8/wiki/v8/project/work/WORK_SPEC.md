# WORK SPEC

> 版本：0.8.0 优化方案 · 文档性质：WORK 需求规格（合同，非建议草稿）
> 前置关系：执行摘要/WORK.md → WORK GOAL → 本 WORK SPEC

## 1. 任务定义

在现有 V8 桌面架构之上，由 WORK Agent 产出一份独立的产品需求规格，完整覆盖 0.8.0 优化方案 W-01~W-29，把"能运行的桌面工具集合"定义为"以『计划 → 执行 → 记录 → 复盘 → 调整』闭环为核心的 Personal OS"。本 SPEC 是这份产品定义的正式合同，供 DESIGN 与 CODE 直接消费。

## 2. 目标对象

- 直接消费者：DESIGN Agent（视觉、布局、动效）与 CODE Agent（架构、数据库、工程）。
- 最终使用者：用户本人（个人效率与学习场景，含高考备考）。
- 评审者：用户本人，用于确认产品方向与优先级。

## 3. 核心问题

V8 功能齐备但模块彼此孤立、首页信息密度过高、复盘退化为数据展示，未形成连续信息闭环，无法快速回答"今天做什么、正在学什么、晚上复盘什么"。本次要解决：在不动摇技术底座与数据安全的前提下，从产品层重新定义模块职责、信息架构、功能逻辑与优先级，让每一次记录最终影响下一次行动。

## 4. 输入材料

优先级自上而下（来自 WORK GOAL 的冻结决定）：

1. `V8_GLOBAL.md` —— 项目长期约束（最高权威，12 条不可破坏项）。
2. `执行摘要/WORK.md` —— 本轮优化范围与方向（W-01~W-29）。
3. `WIKI.md` —— 当前 0.8.0 实际实现状态（源码与 28 张截图）。
4. `deep-research-report.md` —— 研究背景、问题清单与竞品依据。
5. `执行摘要/DESIGN.md`、`执行摘要/CODE.md` —— 下游协作接口与范围参考，不替代 WORK 产品定义。
6. `agent/` 三个 Agent 规范 —— 协作边界。
7. `文字文稿1.docx` —— 已确认为空，不作为有效输入。

## 5. 输出结构

WORK 最终产品定义按以下顺序展开：

1. 产品定位与核心闭环。
2. 模块职责边界（冻结）。
3. 信息架构与导航。
4. 各模块功能逻辑与用户流程（今日 / 计划 / 学习 / 记录 / 复盘 / 工具 / 设置 / 密码本）。
5. 跨模块数据联动规则。
6. 功能优先级与执行顺序（P0 / P1 / P2）。

## 6. 内容要求

- 每个模块须给出：目的、核心信息对象、用户流程、与其他模块的联动点。
- 每个 W 任务从"任务清单"细化为可验收的产品定义，含用户场景、规则与边界。
- 模块职责边界与 `V8_GLOBAL` 第 6 节一致，无重叠、无混淆。

## 7. 信息层级

- 首页只回答"今天"，不承载长期成绩、全量图表、全部项目与笔记。
- 学习以"知识点"为中心节点，向下关联错题、闪卡、笔记。
- 复盘按粒度分级（今日 / 学科 / 周 / 月 / 考试），每级有独立目的与引导问题。
- 视觉层级优先于信息数量；一个对象只有一个主要归属。

## 8. 研究要求

- 需要外部信息时优先官方、一手、权威来源，再使用高质量二手资料。
- 竞品（RemNote / Obsidian / Anki）仅作参考；外部产品有某功能不等于 V8 必须拥有。
- 时间敏感信息必须核对日期；重要事实交叉验证。

## 9. 引用与证据规则

- 明确区分四类：来源原文、外部研究、AI 推断、最终分析结论。
- 不确定处使用明确措辞（"来源未说明""无法确认""据现有信息推测""需验证"）。
- 不凭空补充事实或数据；资料不支持某结论时明确说明。

## 10. 文件格式要求

- Markdown 文件，独立存放于 `wiki/project/`，命名为 `WORK_SPEC.md`。
- 不覆盖、不改写原 `执行摘要/WORK.md`。

## 11. 质量要求

- 结构清晰、模块边界无重叠、结论可验证、覆盖 W-01~W-29、不越界 DESIGN 与 CODE。
- 事实与推断分离；不重复堆砌同一结论。

## 12. 不应包含的内容

- CSS、配色、阴影、卡片圆角等视觉实现（DESIGN 职责）。
- 数据库 Schema、Store、Domain、事件总线、Tauri 代码等工程实现（CODE 职责）。
- W-01~W-29 之外的新功能。
- 把竞品功能当作 V8 的必须项。

## 13. 边界条件

- 遵守 `V8_GLOBAL` 第 22 节 12 条不可破坏项。
- 遵守第 6 节模块职责边界、第 23 节"明确不做"清单。
- 遵守本地优先、V5→V8 迁移、密码本独立安全边界。
- 周期计划只负责规则（W-08）；复盘必须含"下一步"（W-23）。

## 14. 验收标准

- W-01~W-29 全部覆盖，每个 W 任务有明确产品定义。
- 模块职责边界无重叠，信息架构与最终产品树一致。
- 不违背 12 条不可破坏项。
- DESIGN / CODE 能据此直接开始设计与实现。
- 事实与推断已区分，无凭空补充。

## 15. 待确认事项

1. Dexie 表数量：`WIKI.md` 称 18 张、`CODE.md` 称 19 张（+4 新表为 23）；SPEC 落地时以实际工程为准核实，不阻塞启动。
2. 目标用户画像细节：仅知个人使用 + 高考备考，年级、学科等未在材料中说明。
3. 量化产品验收指标：`deep-research-report` 给出的是工程指标（FCP、查询延迟、帧率），产品层的量化指标需另行确认。
