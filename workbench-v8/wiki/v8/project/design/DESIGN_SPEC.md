# DESIGN SPEC

> 版本：1.0 | 阶段：SPEC（GOAL → **SPEC** → PLAN → BROWSER → DESIGN → REVIEW → DELIVER）
> 依据：`V8_GLOBAL.md` / `agent/DESIGN_GLOBAL.md` / `project/work/WORK_SPEC.md` / `执行摘要/WORK.md` / `执行摘要/DESIGN.md` / `执行摘要/CODE.md` / `WIKI.md`（28 张截图 + 源码现状） / `project/design/DESIGN_GOAL.md`
> 说明：本文定义"设计是什么"，不画页面、不写最终 CSS、不进入 UI 生产。区分三类来源：**【用户要求】**（来自冻结的 WORK 产品定义与 DESIGN GOAL）、**【现状】**（来自 `WIKI.md` 与执行摘要）、**【建议】**（DESIGN Agent 专业判断，可被评审推翻）。

## 1. 设计目标

【用户要求】本次设计要解决 V8 视觉层三类问题：

1. **视觉不统一** — 各页面卡片圆角、阴影、间距各自为政，缺统一设计令牌，观感碎片化。
2. **信息组织过度卡片化** — 把所有内容塞进"白色盒子"，Section / List / Panel / Card / Data Block 层级不分。
3. **场景视觉未分层** — 缺少按使用场景（白天 / 夜间 / 分析）分工的视觉体系。

最终让用户在一个**视觉一致、场景适配、信息层级清晰**的工作台中完成"计划 → 执行 → 记录 → 复盘 → 调整"闭环，服务于四个即时问题：今天做什么、正在学什么、有什么要处理、晚上复盘什么。

【建议】把设计目标落为三条可验证主线：① 一套共用 token 结构 + 四套场景主题（A/C/D/F）；② 一套容器层级语义（不"全卡片化"）；③ 一张"首页只回答今天"的信息层级。三者共同服务于"减噪、建立模块连接"，而非增加装饰。

---

## 2. 用户

【用户要求】单一用户，个人使用，以长时间桌面学习与工作为主，含高考备考场景。

【现状】目标用户画像细节（年级、学科、每日使用强度）在材料中未说明。

【建议】据此锁定设计取向：桌面优先、低干扰、长时间耐看、单用户无需协作/多账号考量。年龄与学科未定，不应在视觉上过度"低龄化"或"卡通化"，保持中性、克制、可长期使用的质感。此点列入"待确认"。

---

## 3. 场景

【用户要求】四个核心使用场景：

1. **早晨打开** — 快速回答"我今天做什么"。
2. **学习时段** — 进入学习驾驶舱 / 闪卡复习，保持专注。
3. **晚间复盘** — 理解今天 / 本周表现，形成调整。
4. **全天随时记录** — 快捷备忘 / 任务，低干扰。

【现状】桌面端已具备双窗口（主窗口 + 快捷备忘浮窗）与全局快捷键，具备"无需先打开软件即可进入核心动作"的底座。

【建议】视觉体系按场景而非按模块分工：白天日常 → 晨雾书房；夜间专注/阅读/闪卡/复盘 → 深色夜航；复盘分析（周/月/考试）→ 数据驾驶舱（页面级特例）；Windows 原生感 → Fluent（手动）。场景是主题切换的主轴，模块不决定主题。

---

## 4. 信息架构

【用户要求】顶层信息架构冻结为八类：今日 / 计划 / 学习 / 记录 / 复盘 / 工具 / 设置 / 密码本。九类模块职责边界冻结（Memo / Note / Task / RecurringTask / Knowledge / Mistake / Flashcard / Review / Project），一个对象只有一个主要归属。

【现状】`WIKI.md` 中侧边栏已是六组导航（今日 / 计划 / 学习 / 记录 / 复盘 / 工具）+ 底部设置 / 密码本，与顶层架构一致，不需推翻，只做减法与层级收拢。

【建议】信息架构保持现状骨架，不在导航层新增模块；"未来"作为计划的第五个子页（W-07）纳入，不成为顶层模块。视觉上要区分"模块切换"（重）与"页面切换"（轻），呼应 W-06：模块切换明显，页面切换很轻，避免"进入软件里的另一个软件"。

## 5. 页面树

【用户要求】最终产品树（来自 `执行摘要/WORK.md` 第 6 节，冻结）：

```text
个人工作台 V8
├── 今日
├── 计划（收件箱 / 今日 / 未来 / 周期 / 项目）
├── 学习（总览 / 知识体系 / 错题 / 闪卡 / 成绩 / 阅读）
├── 记录（备忘录 / 笔记）
├── 复盘（今日 / 学科 / 周 / 月 / 考试 / 模板）
├── 工具（番茄钟 / 随机 / 记账 / 倒数日）
├── 密码本
└── 设置
```

【现状】`WIKI.md` 路由现状与上述基本一致，差异点有三处：

| 差异 | 现状 | 目标 |
|------|------|------|
| 计划子页 | 收件箱 / 今日 / 周期 / 项目（4 项） | 增加"未来"（5 项） |
| 学习首页命名 | "学习驾驶舱" | WORK 建议改"总览" |
| 复盘子页 | 已含模板、考试（齐全） | 无结构变化 |

【建议】三处差异均属低风险调整。学习首页命名建议保留"总览"作为导航文案、页面标题仍可为"学习驾驶舱"——避免用户层面出现两个近义入口，最终以 WORK 决策为准（列入待确认）。

## 6. 页面职责

【用户要求】每页须有明确的 Primary Goal / Primary Action / 次要动作（`DESIGN_GLOBAL` 第 5 节）。以下是关键页面职责，均来自冻结产品定义：

| 页面 | Primary Goal | Primary Action | 说明 |
|------|-------------|----------------|------|
| 今日 | 回答"今天做什么 + 今天已做什么" | 勾选 / 进入今日任务 | 只承载"今天"，不含长期成绩、全量图表 |
| 收件箱 | 收集未安排事项 | 转任务 / 转笔记 / 保留 / 删除 | 低摩擦收集 |
| 今日计划 | 今天必须处理的任务 | 新建 / 勾选完成 | 含优先级、置顶 |
| 未来 | 已安排但非今天的任务 | 调整日期 / 安排 | W-07 新增 |
| 周期 | 管理"会反复出现"的规则 | 配置 / 暂停 / 跳过 | 只负责规则，不负责执行 |
| 项目 | 有共同目标的任务与里程碑 | 查看进度 / 管理阶段 | 长期目标聚合 |
| 学习·总览 | 本周学习概览 | 进入薄弱项 / 错题 | 不采用长列表 |
| 知识体系 | 三级树（学科→章节→知识点） | 展开 / 进入知识点中心 | 知识点是中心节点 |
| 错题 | 管理错题与原因 | 新建 / 关联知识点 | 关联错误类型 |
| 闪卡 | 主动回忆复习 | 评价（4 档） | 卡片即核心，无侧栏 |
| 成绩 | 分数与排名趋势 | 录入 / 看趋势 | — |
| 阅读 | 阅读进度追踪 | 更新当前页 | — |
| 记录·备忘 | 快速临时记录 | 输入 + 一键转类型 | 系统输入接口 |
| 记录·笔记 | 长期知识沉淀 | 新建 / 组织分类标签 | 知识点关联 |
| 复盘（5 粒度） | 各自独立目的 | 见第 7 节 | 末尾必须有"下一步" |
| 工具 | 番茄/随机/记账/倒数日 | 各工具各自核心动作 | 继续做减法 |

【建议】每页遵守 `DESIGN_GLOBAL` 的"页面六要素"（标题 / 当前上下文 / 核心任务 / 主内容 / 次内容 / 操作区），避免所有内容同一视觉权重。

## 7. User Flow

【用户要求】核心闭环：计划 → 执行 → 记录 → 数据 → 复盘 → 调整 → 下一轮计划。关键子流程：

1. **输入 → 整理**：快捷备忘（`Ctrl+Shift+Space`）→ 进入备忘录 Inbox → 一键转任务/笔记/错题（W-10/W-11）。
2. **计划 → 执行**：周期规则 → 生成任务实例 → 执行/完成 → 记录 completedAt（W-08）。
3. **学习闭环**：知识体系 → 学习 → 错题 → 闪卡 → 复习 → 掌握度 → 学科复盘 → 下一阶段计划（W-12/W-13）。
4. **复盘反馈**：复盘自动填充数据 → 引导问答 → 产出"下一步" → 回流计划（W-19/W-23）。

【现状】复盘已实现 `autoSummary` 自动汇总 + 引导问答 + 模板；任务完成、番茄、闪卡复习、错题创建等已可汇聚复盘数据（`WIKI.md` 5.5 节 + `CODE.md` C-05~C-10）。

【建议】User Flow 层面 DESIGN 不新增流程，只负责让流程的"关键节点"在视觉上可被一眼识别：例如"待整理备忘"入口、"复盘下一步"出口、知识点中心的"相关错题/闪卡"跳转。所有流程都应能回答"下一步去哪"。

【用户要求】以下是决定体验的核心交互，DESIGN 必须明确其视觉与状态：

| 交互 | 关键点 | 来源 |
|------|--------|------|
| 快捷备忘 | `Ctrl+Shift+Space` 唤起浮窗，`Ctrl+Enter` 保存自动隐藏并同步 | W-10/W-29 |
| 全局搜索 | `Ctrl+K`，跨 9 类对象，结果可直接跳转原对象 | W-28 |
| 闪卡评价 | 四档：😣不会/🤔模糊/🙂会了/😎熟练，初始调度 1/3/7/14 天 | W-16 |
| 任务完成 | 勾选动画 + 完成态，联动项目/周期/复盘 | W-01 |
| 复盘下一步 | 每份复盘末尾必有"下一步"操作区 | W-23 |
| 周期跳过/暂停 | 本次不执行 / 跳过一次 / 暂停 / 恢复 | W-09 |
| 闪卡导入 | CSV 导入 + 粘贴导入，自动匹配/创建学科·章节·知识点 | W-15 |

【现状】闪卡已具备 3D 翻转 + 四档间隔评价 + 5 主题；全局快捷键、快捷备忘双窗口已实现。

【建议】快捷键交互必须避免在输入框聚焦时误触发（`V8_GLOBAL` 第 16 节）；评价按钮目标区要大、状态清晰（见第 12 节）。

## 9. 视觉方向

【用户要求】四场景视觉体系（冻结，`V8_GLOBAL` 第 7 节 + `DESIGN.md` D-01）：

| 主题 | 触发 | 气质 | 适用范围 |
|------|------|------|----------|
| A 晨雾书房 | 白天默认 | 安静 / 温润 / 清爽 / 书房感 / 长期耐看 | 今日/计划/学习/记录/普通页面 |
| C Windows Fluent | 手动切换 | 半透明 / Mica 感 / 原生层次 | 桌面原生感（只换视觉，不改 IA） |
| D 深色夜航 | 夜间默认 | 安静 / 低刺激 / 沉浸 / 专注 | 夜间学习/阅读/闪卡/专注/复盘 |
| F 数据驾驶舱 | 页面级特例 | 数字 / 图表 / 趋势 / 对比 | 仅周/月/考试复盘 |

【现状】`WIKI.md` 当前只有两套主题：`theme.css` 的 `:root`（亮色）+ `[data-theme='dark']`（暗色）。**尚未实现四套场景体系**，这是本次设计最大的增量。

【建议】设计语言遵循 `DESIGN_GLOBAL` 第 9 节：视觉层级优先于信息数量，装饰不得抢夺内容注意力；`DESIGN.md` 明确"深色不是纯黑、不是赛博朋克，数据驾驶舱不是高密度大卡片堆叠"。**A（晨雾书房）与 C（Fluent）的具体色值尚未冻结**（`DESIGN_GOAL` 未决问题 1），本节只定方向、不定死色值。

## 10. Design Tokens

【用户要求】建立统一令牌体系，覆盖颜色 / 字号 / 圆角 / 阴影 / 间距 / 边框 / 动画，四套主题共用同一套 token 结构，令牌以 CSS 变量形式可被工程消费（`DESIGN_GOAL` + `CODE.md` C-24）。

【现状】现状 `theme.css` 已有一组令牌，但命名与目标不一致：

| 类别 | 现状命名（`WIKI.md`） | CODE.md 提议命名 |
|------|------------------------|-------------------|
| 背景 | `--page-bg` | `--color-bg` |
| 表面 | `--surface-card` / `--surface-hover` / `--surface-secondary` | `--color-surface` / `--color-surface-2` |
| 文字 | `--text-primary` / `--text-secondary` / `--text-tertiary` | `--color-text-primary` 等 |
| 边框 | `--border-color` / `--border-focus` | `--color-border` / `--color-border-focus` |
| 强调 | `--accent` / `--accent-hover` | `--color-accent` / `--color-accent-hover` |

【建议】这是关键冲突点，必须在 PLAN 前裁决。DESIGN 建议：**保留现状已实现、已在工程中跑通的语义分组，仅做一次命名的对齐迁移**，避免两套命名长期并存；令牌结构如下（方向性提案，色值除 D 外均待冻结）：

```text
--color-bg / --color-surface / --color-surface-2
--color-text-primary / --color-text-secondary / --color-text-tertiary / --color-text-inverse
--color-border / --color-border-light / --color-border-focus
--color-accent / --color-accent-hover / --color-accent-light / --color-accent-text
--color-success / --color-warning / --color-danger（+ 各自 -light）
--shadow-sm / --shadow-md / --shadow-lg
--radius-sm / --radius-md / --radius-lg / --radius-full
--space-1…8
--transition-fast / --transition-normal / --transition-slow
--font-family / --font-size 系列
```

主题切换建议统一为 `data-theme` 属性 + `mist / fluent / night / data` 四值（与 `CODE.md` C-24 对齐），但**命名对齐的具体时机、是否需要兼容旧的 `data-theme='dark'` 取值，属于实现细节，交由 CODE 决定**。

【现状】强调色现状为靛蓝 `#6366f1`，偏饱和；【建议】"晨雾书房"要求"低饱和强调色、暖白/浅灰蓝底"，与靛蓝存在张力——是否调整强调色、是否让四套主题各自有独立强调色，需冻结（列入待确认）。

## 11. 组件要求

【用户要求】统一容器层级（`DESIGN.md` D-09 + `V8_GLOBAL` 原则 4）：

| 容器 | 视觉特征 | 适用场景 |
|------|----------|----------|
| Section | 无背景或极淡背景，间距分隔 | 页面大分区 |
| List | 行式、分隔线、无卡片背景 | 任务/备忘列表 |
| Panel | 有边框、无重阴影、浅背景 | 设置面板、筛选栏 |
| Card | 有背景 + 阴影 + 圆角 | 重点内容、数据卡 |
| Data Block | 大数字 + 小标签、极简 | 统计指标 |

【用户要求】普通 Card 统一 `radius / padding / border / shadow`，禁止各页面自行定义。

【现状】现状以 `Card` 为主，缺容器层级语义，是"全卡片化"的根源。

【建议】组件由 token 驱动（`DESIGN_GLOBAL` 第 8 节），关键页面按语义选容器：首页的"三件事"用 List、"今日状态"用 Data Block、复盘指标用 Data Block + Chart，而非全部 Card。闪卡页唯一例外——卡片本身即内容核心，允许保留强识别度（`V8_GLOBAL` 第 9 节）。

## 12. 状态设计

【用户要求】交互须有明确状态（`DESIGN_GLOBAL` 第 11 节）：成功 / 失败 / 加载 / 空 / 禁用 / 保存中 / 保存完成。

【建议】重点状态：

| 场景 | 状态设计要点 |
|------|--------------|
| 任务完成 | 勾选 + 行淡出/划线，无夸张庆祝 |
| 闪卡评价 | 四档按钮 hover/选中/禁用；评价后反馈（不可撤销需确认） |
| 快捷备忘保存 | `Ctrl+Enter` 保存中 → 保存完成 → 自动隐藏 |
| 全局搜索 | 输入中 loading、无结果空态、结果分组 |
| 复盘下一步 | 可编辑文本 + 保存态 |
| 周期跳过/暂停 | 明确"跳过本次 / 暂停 / 恢复"的可撤销反馈 |

所有状态遵循"有反馈、可撤销（适用时）、合理默认值"。

## 13. 空状态

【建议】每模块明确空状态，避免"空白恐惧"乱填占位：

| 页面 | 空状态 |
|------|--------|
| 今日 | "今天还没有安排 —— 从收件箱或快速备忘开始" |
| 收件箱 | "收集箱是空的 —— `Ctrl+Shift+Space` 随时记一笔" |
| 错题 | "还没有错题 —— 学习时遇到错误可以这里记录" |
| 闪卡 | "还没有闪卡 —— 导入 CSV 或手动新建" |
| 复盘 | "今日尚未复盘 —— 现在开始，只需几分钟" |
| 全局搜索 | 无结果时的引导 + 搜索范围提示 |

空状态应提供明确的下一步动作入口，而非纯文案。

## 14. 错误状态

【用户要求】错误反馈须明确、可恢复（`DESIGN_GLOBAL` 第 11 节）。

【现状】工程层已有 ErrorBoundary + 数据完整性检查 + 备份恢复流程（`CODE.md` C-19）。

【建议】设计层面明确三类错误视觉：① 表单校验错误（字段级提示 + 不阻塞其他字段）；② 数据/网络类错误（页面级提示 + 重试，但不虚构成功）；③ 闪卡导入/复盘等批量操作的失败（显示成功 N 条 / 失败 M 条 + 失败原因，可局部重试）。错误文案须说明"发生了什么 + 用户能做什么"。

## 15. 响应式

【用户要求】三档体验（`DESIGN_GOAL` 第 5 节 + `DESIGN.md` D-16）：

| 断点 | 设备 | 体验 |
|------|------|------|
| ≥ 1024px | Desktop | 完整功能，侧边栏常驻 |
| 768–1023px | Tablet | 侧边栏可折叠，布局自适应 |
| < 768px | Mobile | 查看 / 快速记录，不搬全部桌面功能 |

【现状】`AppLayout` 已实现：桌面侧栏固定可折叠为 64px 图标模式；移动端侧栏隐藏改为抽屉 + 汉堡 + 遮罩 + 路由跳转自动关闭；`global.css` 已含 44px 最小触控目标、16px 输入字号防 iOS 缩放。

## 16. 可访问性

【用户要求】最低清单（`V8_GLOBAL` 第 18 节 + `DESIGN.md` D-15）：普通文字对比度 ≥ 4.5:1、大文字 ≥ 3:1、全键盘可操作、可见 focus 态、语义化结构、不靠颜色唯一传义、`prefers-reduced-motion` 下减少动画、小屏可完成核心任务。

【现状】`global.css` 已含 `button:focus-visible` 的 `outline`、`.sr-only`、语义化结构、移动端触控目标与字号。

【建议】重点补三处：① 数据驾驶舱的图表不得只用颜色区分（配图例/标签/数值）；② 闪卡四档评价不能只靠 emoji，需有文字标签与键盘可达；③ 主题切换后逐套校验对比度（尤其 Fluent 半透明背景下的文字对比度，需实测确认）。

## 17. 动效

【用户要求】有意义才动 + 支持 `prefers-reduced-motion`（`DESIGN_GLOBAL` 第 15 节 + `DESIGN.md` D-14）。

【现状】`animations.css` 已备齐 fadeIn/slide/scale/pulse/shimmer/flip/cardEnter/celebratePop/ratingPulse 等关键帧与 `anim-*` 工具类，含列表交错入场。

【建议】动效收敛到四类目的：页面进入（淡入+轻微上移）、闪卡翻转（3D flip）、任务完成（勾选+轻微缩放）、数据更新（数字滚动/渐入）。**禁止**所有元素同时飞入、无意义弹跳；`celebratePop` 等装饰动画仅在任务完成等明确反馈点使用，不滥用。`prefers-reduced-motion: reduce` 下全部压到近乎零时长。
