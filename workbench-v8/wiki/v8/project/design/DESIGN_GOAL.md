# 个人工作台 V8 — DESIGN GOAL

> 版本：1.0 | 阶段：GOAL（GOAL → SPEC → PLAN → BROWSER → DESIGN → REVIEW → DELIVER 的第一步）
> 依据：`V8_GLOBAL.md` / `agent/DESIGN_GLOBAL.md` / `执行摘要/DESIGN.md`
> 说明：本文件只定义"本次设计要解决什么"，不画页面、不写 CSS、不进入最终 UI 生产。

---

## 1. 设计目标

本次设计要解决 V8 视觉层当前存在的三类问题：

1. **视觉不统一** — 各页面卡片圆角、阴影、间距各自为政，缺少统一设计令牌，整体观感碎片化，长时间使用产生不一致感。
2. **信息组织过度卡片化** — 容易把所有内容装进"白色盒子"，Section / List / Panel / Card / Data Block 层级不分，首页、学习页、复盘页容易变成信息墙，抢夺用户对核心内容与动作的注意力。
3. **场景视觉未分层** — 缺少按使用场景（白天日常 / Windows 原生 / 夜间专注 / 复盘分析）分工的视觉体系，无法在不同时段与任务下提供合适的刺激强度。

最终设计要让用户能够：在一个**视觉一致、场景适配、信息层级清晰**的工作台中，完成"计划 → 执行 → 记录 → 复盘 → 调整"的核心闭环，而不被视觉噪声干扰。

> 设计服务于"今天做什么、正在学什么、有什么要处理、晚上复盘什么"四个即时问题，而非堆砌数据展示。

---

## 2. 用户与场景

**谁使用**：单一用户（个人使用），以长时间桌面学习与工作为主。

**什么时候使用**：
- 白天 — 日常计划、学习、记录、任务管理
- 夜间 — 学习、阅读、闪卡复习、复盘
- 复盘时 — 周 / 月 / 考试复盘，看数据、看趋势、形成下一步行动

**核心场景**：
1. 早晨打开工作台，快速回答"我今天做什么"
2. 学习时段进入学习驾驶舱 / 闪卡复习
3. 晚间进入复盘页，理解今天 / 本周表现并形成调整
4. 全天随时快速记录（备忘 / 任务）并保持低干扰

---

## 3. 最终设计产物

- **Design System** — Design Tokens（颜色 / 字号 / 圆角 / 阴影 / 间距 / 边框 / 动画）+ 四套主题（晨雾书房 / Windows Fluent / 深色夜航 / 数据驾驶舱）
- **容器与卡片规范** — Section / List / Panel / Card / Data Block 统一定义
- **关键页面布局规范** — 首页 / 学习驾驶舱 / 闪卡 / 复盘双栏
- **Wireframe** — 关键页面线框图
- **High Fidelity UI** — 四套主题下的关键页面高保真
- **闪卡背景设计** — 至少 5 种（晨雾 / 夜空 / 森林 / 琥珀纸页 / 极简）
- **动效规范** — 有意义才动 + 支持 `prefers-reduced-motion`
- **响应式方案** — Desktop / Tablet / Mobile 三档
- **可访问性规范** — 对比度 / 键盘 / focus / 语义化清单
- **Design Spec** — 可直接交付 CODE Agent 的实现说明

---

## 4. 设计范围

**包含**：
- 四套视觉体系的主题与令牌定义
- 统一 Design Token 体系
- 容器层级与卡片系统统一
- 首页、学习驾驶舱、闪卡、复盘页的布局与视觉
- 闪卡背景设计（≥5 种）
- 动效、可访问性、响应式规范

**不包含**：
- 产品功能增减、信息架构改动、业务规则变更（属 WORK Agent）
- 工程实现、数据库结构、状态管理（属 CODE Agent）
- 改变已确认的技术底座与核心信息架构
- 为"看起来丰富"而新增的装饰性功能

---

## 5. 平台与约束

**主平台**：Windows 桌面应用（Tauri 2）
**兼容形态**：Web（核心前端逻辑不依赖 Tauri 才能运行）

**响应式三档**：

| 断点 | 设备 | 体验 |
|------|------|------|
| ≥ 1024px | Desktop | 完整功能，侧边栏常驻 |
| 768–1023px | Tablet | 侧边栏可折叠，布局自适应 |
| < 768px | Mobile | 查看 / 快速记录，不搬全部桌面功能 |

**技术约束（影响设计落地）**：
- React 19 + CSS Modules + ECharts 6
- 设计令牌需以 CSS 变量形式可被工程消费
- 桌面优先但不破坏 Web 可用性

**不可破坏项**：四场景视觉体系、核心信息架构、本地优先数据原则、密码本独立安全边界、现有技术底座。

---

## 6. 成功标准

设计完成的标准：

1. 四套主题视觉冻结，令牌完整，且四套主题共用同一套 token 结构
2. 普通卡片统一 `radius / padding / border / shadow`，无页面各自定义
3. 关键页面（首页 / 学习 / 闪卡 / 复盘）有明确布局规范与高保真
4. 容器层级清晰，首页 / 学习 / 复盘不再"全卡片化"
5. 闪卡有 ≥5 种背景，且文字始终是第一视觉层
6. 动效有目的，支持 `reduced-motion`
7. 可访问性达到对比度 / 键盘 / focus / 语义化最低清单
8. 产出可直接交付 CODE Agent 的 Design Spec
9. 设计未改变已确认的产品目标、信息架构与不可破坏项

## 7. 未决问题

仅列出真正影响设计方向的问题：

1. **晨雾书房（A）与 Windows Fluent（C）的具体色值尚未冻结** — 当前仅深色夜航（D）有明确 hex。A 与 C 的色值冻结会直接影响 Design Token 能否定稿。
2. **数据驾驶舱（F）的适用边界** — 是否仅限周 / 月 / 考试复盘，还是也覆盖今日复盘与学科复盘？这决定 F 是"少数页面专用"还是"复盘体系通用"。
3. **自动主题的昼夜切换判定** — 以固定时段、系统主题还是日出日落为准？影响自动模式预期，但对静态视觉设计影响较小，可在 SPEC 阶段确认。
