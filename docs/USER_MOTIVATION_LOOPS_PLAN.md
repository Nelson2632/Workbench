> 修订日期：2026-10-28
> 状态：研究与源码核对完成；实现、运行验证尚未执行。
> 审查基线：main @ `97376e706f7f455bb290a25c07ababb397a862f0`。以下“现状”仅指该提交的静态源码事实。
> 目标：更容易开始，真实确认进展，允许计划恢复，让经历留下来。
> 权威规范：[V9 Personal OS v1.7](./V9-Personal-OS-v1.7.md)。本计划细化交付顺序，不自行覆盖冻结的 Domain / Schema / Runtime 契约。
> 原型：[Motion Lab](./experiments/motion-lab.html)，只作视觉实验，不是生产实现或验收证据。

## 1. 本次调整

保留 Start / Complete / Recover / Memory 四个方向，将宽泛的“积极性优化”收敛为三个可独立验收的增量：

1. **R1 · 保存可信、晚上能结束**：快速记录不丢输入；完成命令与投影状态清楚；晚间收口允许空反思。
2. **R2 · 首页容易行动、计划可以恢复**：Now 一项、Next 最多四项；单项改期与撤销；逾期列表不占据首屏中心。
3. **R3 · 真实记忆与克制反馈**：Daily Memory 更新正确、能回到来源；三个全局主题和 Review Data Scope 分别验收。

先完成日常高频路径，再评估扩展。声音、积分、排行榜、连续打卡、推荐引擎、年度报告、PDF 导出、复杂诊断面板不进入这三个增量。批量恢复、持久化拆分/暂存/放弃、“往年今天”放入后续候选，不与近期体验修复捆绑。

这是范围与次序调整，不承诺未经验证的留存提升或固定完成日期。

## 2. 研究依据与适用边界

检索日期：2026-10-28。优先使用原始论文、原始研究摘要与 W3C 官方解释。这里的研究用于支持设计方向，不证明某个按钮、动画或“五分钟”时长有效。

| 证据 | 能支持什么 | 对 Workbench 的设计推断 | 不能推出什么 |
|---|---|---|---|
| [E1] Gollwitzer & Sheeran, 2006，实施意图元分析 | 预先明确情境与行动，有助于将目标转成行动 | Now 明确一件事；可选填写具体第一步，如“打开数学卷，先做第 1 小问” | 不证明五分钟是最佳时长；不能强迫补填计划字段 |
| [E2] Breines & Chen, 2012，四项实验 | 接纳失败的自我态度可以与改进动机并存 | 恢复入口用事实和可执行动作；不强迫解释原因；允许结束一天 | 实验中的心理干预不等于 App 文案；不承诺降低焦虑或提高成绩 |
| [E3] Harkin et al., 2016，进展监测元分析 | 记录和查看目标进展可支持目标达成 | 展示可信的已完成事项，减少手动重复记录 | 不证明更密集的仪表盘、更频繁提醒或奖励动画更好 |
| [E4] WCAG 2.2 SC 4.1.3，AA | 状态消息需可被辅助技术识别，无需抢焦点 | 保存、失败、同步状态采用恰当语义；保留可恢复入口 | 源码里出现 aria-live 不等于读屏验收通过 |
| [E5] WCAG 2.2 SC 2.3.3，AAA | 非必要交互动效可关闭 | 尊重系统减少动态效果；静态状态仍清楚 | 不得宣称它是 WCAG AA 的强制条款或整站已合规 |

**证据强弱：** E1/E3 是跨研究汇总，E2 是原始实验，E4/E5 是规范解释；具体布局、默认关闭提醒、最多四个 Next、短反馈与拆分发布均为本项目的产品/工程判断。Memory 的情感价值、五分钟入口是否有用，需要本人实际使用反馈。

## 4. 共同产品边界

- Today 保持 Orientation → Capture → Action Space → LIFE/PLAY → Memory；Today Plan 是唯一默认 Panel，Now 为 Flow。
- 三套全局主题：Mist / Fluent / Night；Review Data Scope 只作用于复盘 Canvas 及其专属控件，不进入全局主题枚举。
- 捕获只需标题。第一步说明、时长、学科、计时、反思均可跳过。
- 21:00 不能默认被解释为“应该结束学习”。近期保留主动收口；如果已有提醒，保持用户可关闭、可改时间，不新增固定 21:00 提醒。
- 不以使用时长、签到天数、闭环完成率衡量用户价值；不上报个人行为数据。
- 不在本次计划中将所有本地数据泛称为“全部加密”；安全能力按现有安全契约逐项验证。
- Night Shutdown reflection、Daily Memory reflection 和 Review 回答保持各自归属，聚合器不得覆盖人写内容。

## 5. R1：保存可信、晚上能结束

### 5.1 捕获与转换

覆盖 Today Capture、Inbox 新增、Inbox → Task；审查项目/周期/素材转换的两步写入。后者目前是先新增目标再 discard 源，若后一步失败可能留下重复转换机会，需事务化或明确可恢复协议，不应静默重试整个流程。

提交路径：
1. 首次确认形成一次业务意图，生成 commandId；同一未结束意图的双击/Enter 重复触发复用它，并在 UI 防重入。
2. 固定提交内容快照。pending 中若允许继续输入，只在当前文本仍等于已提交快照时清空，避免清掉新输入。
3. 保存失败保留文本、焦点上下文、错误和重试；只有确认未提交才重新执行写入。
4. 结果不明时先查询 commandId 与目标事实；已提交就重载事实，不另造一条。用户主动编辑内容重新提交，构成新意图。
5. 幂等命中不能把 `result: null` 一概当失败；Inbox 转换应能重新查询既有 sourceTaskId 并返回已有产物。
6. 命令去重记录有保留期限，需核实清理策略；超过窗口的转换仍应由源实体的转换状态/产物引用阻止重复，不宣称无限期 exactly-once。

### 5.2 提交、投影与反馈

必须保留“事务已提交即命令成功”的语义。原计划中“在 afterCommit 内发投影完成反馈”与当前顺序不兼容，替换为：

| 状态 | 用户可见信息 | 允许的下一步 |
|---|---|---|
| submitting | 正在保存；阻止同意图重复提交 | 等待，保留输入 |
| committed | 任务事实已保存；按真实事实更新勾选语义 | 不再执行该写意图 |
| projecting | 回顾正在更新 | 不要求用户再点完成 |
| projected | 投影确认完成；至多一次短完成反馈 | 正常继续 |
| commitFailed | 未保存；明确错误 | 同意图安全重试 |
| projectionFailed | 已保存，回顾暂未更新 | 仅重试/重建投影 |

这张表是拟实现协议，不是现有 API 声明。实现前选择最小的可确认方案，例如按命令关联投影结果，并明确受影响投影集合（任务完成/撤销涉及 Timeline、Daily Memory）。不得等待整个 EventBus 的所有订阅。

注意：
- 不把 publish 返回或测试辅助 flush 当作生产确认。
- 确认需传播投影失败；Promise.allSettled 本身不代表成功。
- 在 Lane 内等待投影，而投影再次排入同一 Lane，会造成死锁；确认过程应放在不阻塞同队列的位置，或采用经契约审查的事务内投影方案。
- afterCommit、事件发布应分别隔离错误，避免 UI 回调失败阻止事件发布。
- 当前 after_domain_commit 故障注入位于保护块外，需补测“数据库已提交但调用方收到异常”的结果不明路径。
- 本次只保证已审计运行上下文；模块内 FIFO 不自动提供跨窗口串行保证。若同一事实可由浮窗写入，需另验证 DB 事务/幂等策略。
- 保留 data-v9-done / data-v9-done-title / data-v9-done-glow；持久完成状态与一次性动画触发分开。历史重载不播放奖励。
- UI 操作尽量改为显式 setCompleted(id, desiredState, intentId) 语义；具体命名由实现决定。事务内检查最新实体，不在队列外以旧 Store 状态取反；目标不存在时不能发完成事件。

### 5.3 事件与恢复

对照 PROJECTION_CONTRACT、Domain 生命周期确认 update / undo-complete / archive / permanent-delete 的事件与投影含义，不能简单“所有删除都抹历史”。事务内日志与事实同步提交；增量投影、冷启动重建结果一致。

恢复只重放/重建派生数据，不重新执行已提交的用户写入。修复历史投影前先预览/备份，不改写原始完成时间。

### 5.4 晚间最短路径

流程：真实完成与记录摘要 → 可选处理遗留 → 可选一句话/明日重点 → 完成收口 → 结束或返回 Today。

- reflection 可为空，原因可为空；空值对应界面不显示空标题。
- 页面保存失败保留表单；重复提交不生成两份同日收口。
- Review 作为次要可选入口；成功通知只确认收口，不继续催促。
- 原有五类复盘模板继续用于主动深入复盘；不把它们塞进晚间最短路径。
- 不自动把 tomorrowFocus 文本转成新 Task，以免无意生成重复待办。

**R1 通过门槛：** A01–A04 / A06 的关键路径测试通过；已提交与投影失败能区分；空反思可结束；失败不丢输入。若投影确认需要大规模 Runtime 改造，先提交契约差异说明和最小方案，不通过伪确认绕过要求。

## 6. R2：首页容易行动、计划可以恢复

### 6.1 Start

- 单一选择器生成 Now、Next、Plan，包含普通与周期任务；不能分两套重复队列。
- Now 至多一项；用户明确选择优先，默认候选沿用既有优先级/置顶排序并加稳定 tie-break，不引入推荐算法。
- Next 为余下候选最多 4 项。Today Plan 提供全量入口；同屏摘要行排除 Now/Next，清楚标注“其余 N 项”，全量管理页仍能查看全部。
- 已选任务未完成、未移除时不因后台刷新跳走；删除/改期/跨日后重新校验，不保留悬空引用。
- “开始”打开任务上下文；可选“先做 5 分钟”，不自动记满五分钟、不强制计时器、不暗示已完成。
- 当前 Task 未证明有完整 started 生命周期；首期当前选择可采用可丢弃的会话 UI 状态，明确不构成已开始事实。需要持久化开始时间时先补领域契约。
- 无任务：可捕获一件事，或去选择已有事项；不虚构任务填空。

### 6.2 Recover

先做**单项改期 + 撤销**，作为本轮最小可用恢复路径：
- 清楚区分“计划日期”和真实 deadline；改期不偷偷改变 deadline。
- 保存旧日期，提交成功后提供 5–10 秒撤销；撤销也是命令。
- 撤销前检查实体是否又被修改，避免覆盖新编辑；冲突时说明并保留当前事实。
- 周期任务改期只影响本次实例，不默认改整个规则；展示影响范围。
- 逾期摘要放在行动区的次要位置，默认折叠，展开可查看全部；保留日期事实，使用中性文字和克制颜色。

后续候选必须先定义语义：
- **拆分**：父子关系、原任务完成规则、重复统计、撤销边界。
- **暂存**：在哪找回、是否保留日期、如何重返计划。
- **放弃**：独立于完成/永久删除，是否归档、历史如何保留。
- **批量改期**：先选范围和预览；声明原子或部分成功策略；撤销时处理并发改动。

现有 Task 未证明具备这些字段，不能用清空日期冒充暂存、标完成冒充放弃，或把未完成原任务直接删除。

**R2 通过门槛：** Now ≤1、Next ≤4；普通/周期任务无重复摘要；单项改期可恢复；关键路径鼠标和键盘均可用；不新增强制字段。

## 7. R3：真实记忆与克制反馈

### 7.1 Memory

- 复用 Timeline / Daily Memory 与现有事实表；不另建一份任务完成载荷。
- 对完成、取消完成、编辑日期、删除等事实变化建立明确失效策略；合并同一日期的刷新，防止事件风暴和旧计算覆盖新结果。
- 影响日期包括旧日与新日；首次进入和恢复前台时校验当前日。跨午夜、历史编辑、恢复备份均要检查。
- ISO 时间戳保留绝对时刻；“今天”按统一的本地日工具计算。日期字符串直接按其业务日期处理；不得对所有字段无差别再换时区。
- 首期 Today 只显示简短事实及少量真实来源入口；无记录时隐藏记忆摘要，不制造全零成绩单。
- 聚合数据明确可追溯；来源缺失、归档、永久删除遵守契约，不能打开空白页面。
- Night Shutdown 的人写反思不自动复制到 Daily Memory；重建不能覆盖已有 reflection。
- “往年今天”延后：要处理隐私、主动隐藏、闰日、来源删除及旧记录归日，不能只按月日拼接。

### 7.2 动效与无障碍

- 复用现有 v9-motion.css / motion.css / theme.css 的时长与材质来源，先梳理覆盖关系，不再新建通用 duration 系统。
- Mist 纸墨、Fluent 深度、Night 局部光、Review Data 数据确认；保留相同操作含义，不把 Review 样式应用到全局壳。
- 普通任务一次轻反馈，不引入“重要里程碑”的自动评分规则；声音继续不做。
- 完成后行可短暂收束，但不能以等待动画阻塞保存。动画只按本次确认触发，静态完成态不依赖动画。
- Reduced Motion 下仍有勾选/文字；错误不只靠抖动或颜色。
- 状态播报不抢焦点；删除/完成导致行移除后，焦点回到合理的下一项或列表入口。
- 静态 a11yPolicy 继续保留，但补浏览器交互与 macOS VoiceOver 人工走查；不能把 placeholder 存在、CSS 包含令牌等同于可用。

**R3 通过门槛：** 相关投影实时/重建一致、人写内容不变；跨本地午夜准确；来源可打开；三全局主题及 Review 页面范围、减少动效、键盘和读屏路径可用。

| W0 | 跑当前基线，复现审查表，确认契约差异、数据备份、日期与通知调用链 | 无 | S |
| W1 | Today/Inbox pending、输入快照、失败重试、转换返回值与原子性 | W0 | M |
| W2 | 显式完成意图、事件补齐、提交/投影确认、失败修复 | W0；与 W1 对齐意图协议 | L |
| W3 | 可跳过反思、保存错误、收口出口与通知 | W0 | S |
| W4 | Now/Next/Plan 选择器、会话当前项、单项改期撤销 | R1 通过 | M |
| W5 | 记忆刷新、日期边界、来源跳转、动效与可访问性 | W2/W4 | M–L |

S/M/L 是相对工作量，W2 不确定性最大。W0 后才能估人日；不以固定日期挤压验证。每个包独立提交，R1 / R2 / R3 分别验收。若 W2 改动过大，可先交付 W1/W3 的明确改进，但必须注明“完成反馈闭环未验收”，不把 R1 整体标完成。

## 9. 验证矩阵与发布门禁

| 场景 | 必须断言 |
|---|---|
| Capture 写入失败；保存期间输入新文字 | 原文字/新文字均不意外丢失，错误可见，未误报成功 |
| 双击、重复 Enter、重试结果不明命令 | 同业务意图只产生一份事实；新意图可正常提交 |
| 完成后投影延迟/失败，UI 回调抛错 | 数据已保存状态真实；无重复业务写；事件不被 UI 异常截断；投影可恢复 |
| 完成后取消、改日期、删除、重启/重建 | 事实与相关投影一致；无孤儿或多计数；遵守历史保留契约 |
| 动画中切页再返回，旧完成项重新挂载 | 不重播奖励，不丢语义状态 |
| 0/1/5/100 个普通与周期任务 | Now/Next 数量正确、排序稳定、摘要不重复 |
| 改期后撤销；期间再次编辑/删除；周期实例 | 不覆盖新编辑，不修改整套周期规则，失败有清楚恢复 |
| 空反思提交；无完成记录的一天 | 能正常收口，无虚构成果、无必填阻断 |
| 上海时间 00:00–08:00；午夜前后完成；跨日恢复前台 | Today/Shutdown/Memory 对业务日期一致 |
| 记录缺失、历史日期编辑、刷新并发 | 来源可恢复/解释，旧日新日都更新，人写反思不被覆盖 |
| 键盘、VoiceOver、Reduced Motion、三主题/Review Scope | 操作可达、状态可知、焦点合理，无动效依赖 |
| 离线及重启 | 核心路径可用，无新增外部分析请求 |

## 10. 本地评估与完成定义

首期采用受控任务走查 + 简短使用日志，不建设行为分析平台：
- 可靠性硬指标：误报保存成功、丢输入、同意图重复写、错误覆盖人写反思，测试场景中均为 0。
- 可用性：记录开始路径操作次数、恢复是否找得到、晚间收口是否可无文字结束；不把点击“开始”当作现实中已学习。
- 可选一周自用：每次只记“哪里卡住/是否多余/是否省事”，允许不记录。少量个人反馈只作方向判断，不声称统计显著。
- 如需自动诊断，只记录命令类型、耗时和错误码等最少信息；不收集日记/任务正文，不出网，保留周期与清除方式先定义。

每个工作包交付：具体用户路径、成功/失败/恢复行为、关键测试证据、契约/Schema 变更说明、未验证事项。最终完成以三个增量的门槛为准，不能以静态原型、历史全绿报告或文档勾选代替真实运行。
